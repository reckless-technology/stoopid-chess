## The refactor (done, merged into `evaluation`)

`Board` is `Position`, one file `src/StoopidChess.Core/Position.cs` holding state, make/unmake, legal
move generation (`GenerateLegalMoves`, `GenerateLegalCaptures`, `IsLegal`) and position editing
(`Empty`, `Setup`, `Place`, `Clear`, `SetSideToMove`, `SetCastlingRights`; `PositionBuilder` is gone).
`MoveNotation` folded into `Move` (`ParseUci`, `ToLongAlgebraic`). `PieceType` is `Piece`, `Colour` is
`Color` (aliased in the GUI). American spelling in code is now a CLAUDE.md convention.

## SPSA tuning (in progress, stopped part way)

- **Infrastructure** (commits `4d7580b`, `2197df7`): `EvaluationParameters` holds 27 tunable values
  defaulting to the constants in `Evaluator`; each is a UCI spin option (`uci` lists them, `setoption`
  sets them, shared by the searcher and the `eval` command). `tools/spsa.py` reads the options from the
  engine and runs fishtest-style SPSA with paired fastchess matches.
- **The run:** `python tools/spsa.py --iterations 500 --games 8 --tc 4+0.04 --r-end 0.02 --concurrency 8`,
  about 17 s per iteration on 8 cores. Stopped at iteration 162 of 500. Its state, CSV log and console
  output are committed under `tools/spsa-runs/2026-09-19-partial/` and copied beside this note.
- **To resume on another machine:** build (`dotnet build src/StoopidChess.Uci -c Release`), copy
  `tools/spsa-runs/2026-09-19-partial/state.json` to `tools/spsa-state.json` and `log.csv` to
  `tools/spsa-log.csv`, fix the fastchess and openings paths in `tools/spsa.py` (they point at
  `C:\Users\jonny\tools\...`; `--fastchess` and `--openings` override them), then run the same command
  with `--resume`. Or start afresh; 162 iterations is early.
- **Values at iteration 162** (default in brackets), the clearest trends so far: RookValue 511 (500),
  QueenValue 985 (1000), RookMobility 5.5 (4), KnightMobility 5.2 (6), KnightOutpostBonus 25 (20),
  ShelterRank2 14.5 (17), ShelterMissing -16 (-20), PassedRank6 74 (60), PassedRank7 117 (100). Everything

- **When the run finishes:** round the values, put them in as the new constants in `Evaluator.cs`

  against a baseline published from the current HEAD; keep only on a clear win, exactly as for any
  other change.

## Method, in short

One change per commit, judged by `tools/selfplay.ps1` (100 games at 12+0.12, 8 concurrent) against
`C:\Users\jonny\tools\stoopid-baseline` (republish it from HEAD after each accepted change with
`dotnet publish src/StoopidChess.Uci -c Release -o <dir>`). Keep at about +30 or better; a result between
about +15 and +25 gets a second 100 games and is judged on the 200; log everything. Never rebuild while a
match runs from `src/StoopidChess.Uci/bin/Release`. Speed comparisons use `bench 9` or deeper with
`DOTNET_TieredCompilation=0`, because the short default bench is dominated by JIT warm-up. The
pre-commit hook enforces `dotnet format`; enable it with `git config core.hooksPath .githooks`.
